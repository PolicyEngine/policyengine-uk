Fix `calculate_dependency_contributions` for monthly variables (Class 1 NI, child benefit amounts, fuel duty, energy price guarantee). When the target, or a variable it reads directly, has a monthly definition period and its months hold non-zero values, restoring the value over the year raised "Inconsistent input", and for a monthly target it left the simulation with those months at zero. The function now zeroes each dependency on a throwaway branch, over the year and any other period the target read it, and holds every other variable the target read at the value it read; a read on another branch changes on a branch of that name. So it never changes the simulation passed in, and the contributions of a target that adds and subtracts what it reads sum to that target. It reads the dependencies from the target's latest calculation over the year asked for, not the first calculation the trace shows over any year, and raises for a target that reads its own value within that year. A monthly target's dependencies are now what its months read, not the target itself; the same variable read on another branch stays a dependency.
