Fix `calculate_dependency_contributions` for monthly variables (Class 1 NI, child benefit amounts, fuel duty, energy price guarantee). When the target, or a variable it reads directly, has a monthly definition period and its months hold non-zero values, restoring the value over the year raised "Inconsistent input", and for a monthly target it left the simulation with those months at zero. The function now recalculates the target on a throwaway branch with a clone of the tax-benefit system: the dependency is zero wherever the target read it (each period, and on each branch the target's formula reads), and every other variable it read keeps the value it read. So it never changes the simulation passed in, and the contributions of a target that adds and subtracts what it reads sum to that target. It takes the dependencies from the target's latest calculation over the year asked for that gave the value the simulation holds, not the first calculation the trace shows over any year. It handles years that start in another month, monthly stocks, branches a formula names afresh (`marginal_tax_rate`) and labour supply responses, and it raises for a target that reads its own value within that year. A monthly target's dependencies are now what its months read, not the target itself; the same variable read on another branch stays a dependency.
