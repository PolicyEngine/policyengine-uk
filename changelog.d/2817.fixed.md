Fix `calculate_dependency_contributions` for monthly variables (Class 1 NI, child benefit amounts, fuel duty and the energy price guarantee, say). Where the target, or a variable it reads directly, has a monthly definition period and its months hold non-zero values, restoring the value over the year raised "Inconsistent input", and for a monthly target it left the simulation with those months at zero. The function now recalculates the target on a throwaway branch with a clone of the tax-benefit system, with the dependency zero wherever the target read it and every other variable it read in the simulation holding the value it read, apart from the limitations its docstring lists. So the simulation passed in stays as it was, apart from what the function's own calculation of the target stores or drops, and the contributions of a target that only adds and subtracts float variables it reads sum to that target, unless `top_n` drops some. The function takes the reads from the target's latest calculation over the period asked for that gave the values the simulation holds, not from the first calculation the trace shows over any year, and a formula that read no variables has no contributions. It also handles years that start in another month, a yearly target over a month, monthly stocks, branches a formula names afresh (`marginal_tax_rate`) and labour supply responses. It raises for a target held as an input and for values no calculation in the trace gave and the formula does not give without reading a variable, and, where a float dependency needs a recalculation, for a target that reads its own value within the period and for a read on a branch of a subset of households. A value the recalculation holds that the simulation calculated stays calculated to `supplied_input` and `stored_as_input` (`record_model_value`), so a formula that asks either about what it read takes the path it took in the simulation. A monthly target's dependencies are now what its months read, not the target itself; the same variable read on another branch stays a dependency.
