`Simulation` now refuses integer enum columns that it did not record itself in a `UKSingleYearDataset`, a `UKMultiYearDataset` or their `.h5` files, where an in-range survey code would load as the wrong member: `council_tax_band` code 1, for instance, would load as band B. To migrate, map survey codes to member names with the survey's code list, and decode genuine 0-based positions to names with the enum declaration that encoded them. DataFrames and policyengine-core datasets still give 0-based positions, and the loader checks each one at the width it arrives in. Each load also checks the positions it recorded against the enum it recorded them under.
